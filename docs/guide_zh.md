# 项目导读（中文）

这份文档把我们聊过的做市概念和代码一一对应起来，方便你读代码、复现实验、准备面试。英文 README 面向招聘方，这份面向你自己。

## 1. 一句话说清这个项目

用币安的真实实时行情，模拟一个做市商在现货上挂买卖单：判断挂单什么时候会被成交，然后像做市团队那样拆解盈亏，回答"钱从哪来、亏在哪"。

## 2. 一次模拟的完整流程

```
币安 websocket ──► feeds/ ──► 标准化事件 ──► engine.py ──► 每个事件依次做 4 件事：
  (现货盘口、逐笔成交、                           1. 到期的下单/撤单生效（模拟延迟）
   20 档深度、永续合约盘口)                        2. 更新真实盘口，检查我们的挂单有没有被成交
                                                 3. 更新信号（波动率、永续偏离、盘口不平衡）
                                                 4. 问策略要新报价，偏离太多就撤单重挂
                          │
                          ▼
                  analytics.py ──► report.py ──► 报告（盈亏拆解、markout、图表）
```

- **实时纸面交易**（`paper`）和**回放回测**（`backtest`、`sweep`）走的是同一个 `Engine`，区别只是事件来自 websocket 还是文件。
- 纸面交易会同时把收到的行情录下来。用 `reproduce` 回放，结果和实时跑的逐笔一致。这点面试时可以讲：**回测和实盘用同一套代码，是避免"回测好看、实盘不一样"的基本功。**

## 3. 概念和代码的对应

| 概念 | 含义（回顾） | 代码位置 |
|---|---|---|
| maker / taker | 挂单等人来吃的是 maker（我们），主动吃单的是 taker | `exchange.py`：我们的单全部是 post-only 挂单 |
| 价差收入 | 买在 mid 下面、卖在 mid 上面，赚中间的差 | `analytics.py` 的 `spread_capture` |
| 逆向选择 | 跟你成交的人比你知道得多，成交后价格往不利方向走 | `analytics.py` 的 `markouts`，看成交后 0 秒到 60 秒的曲线 |
| 排队位置 | 同一价格先挂先成交，排在后面的要等前面的被吃完 | `exchange.py` 的 `queue_ahead` |
| 延迟 | 看到行情到订单生效之间的时间差，撤单可能来不及 | `exchange.py` 的 `latency_ns`，测试见 `test_cancel_can_lose_the_race` |
| 库存风险 | 手里攒了仓位，价格一动就盈亏 | `analytics.py` 的 `inventory`；策略 v1 的库存偏移 |
| Avellaneda-Stoikov | 经典做市模型：库存多了就把报价整体往下压，波动大就挂宽 | `strategies/quoting.py` 的 `AvellanedaStoikov` |
| 公允价 / 信号 | 用盘口不平衡、永续合约偏离去估"真实价格" | `signals.py`，策略 v2 `AvellanedaStoikovSignal` |
| 手续费 / 盈亏平衡费率 | 毛利润除以成交额，就是能承受的最高费率 | `analytics.py` 的 `breakeven_fee_bps` |

### 模拟撮合的规则（最重要的部分）

回测做市策略，最难也最容易自欺欺人的就是"我的单到底会不会成交"。本项目的规则（详见 `exchange.py` 开头的注释）：

1. **成交价穿过我的价格**：比如有人以低于我买价的价格卖出，按价格优先原则我一定先被成交，算全部成交。
2. **盘口越过我的价格**：真实盘口的卖一价跌到了我的买价或以下，说明有卖家挂到了我的价格，他会跟我成交。
3. **在我的价格上成交**：先吃掉排在我前面的量，剩下的才轮到我。
4. **排队估计**：新挂的单默认排在这个价位所有已有挂单的后面，之后只会随着成交和撤单往前挪。

面试时主动讲这些假设和它们的局限（比如"我假设我的单太小不影响市场"），比只报收益率更有说服力。

## 4. 怎么读报告

每次运行会生成 `dashboard.png`，四张图：

1. **价格和我们的成交**：灰线是中间价，蓝色三角是我们买入，橙色倒三角是卖出。注意观察成交是不是经常出现在价格快速移动的时候。
2. **库存**：以"单"为单位（1 单 = 100 USDT）。v0 没有库存控制，经常顶到上限；v1、v2 会主动往 0 拉。
3. **累计盈亏拆解**：毛利润 = 价差收入 + 库存盈亏。如果价差收入接近 0 甚至为负，说明我们大部分成交发生在价格已经穿过我们的时候。
4. **Markout 曲线**：横轴是成交后的时间，纵轴是按那时的中间价算，这笔成交赚了多少基点。曲线往下走，就是逆向选择。

`sweep` 生成的对比表里，"gross = break-even fee" 这一列最关键：它告诉你手续费低于多少这个策略才不亏。

## 5. 实验结论

见 [../RESULTS.md](../RESULTS.md)，那里有全部数字和图表，这里只写要点和解读。

**实验怎么设计的**：每个币种先录 60 分钟行情，前 20 分钟用来研究信号、定参数（校准），后 40 分钟回放检验（样本外）。另外单独跑了两场 60 分钟的实时纸面交易，三个策略在同一条实时行情上同时报价，参数在开跑前就定好，完全是样本外。

**结论**：

1. **全部亏钱。** 不算手续费，三个策略在两个币种、四种延迟下，每成交 1 USDT 亏 0.35 到 2 个基点。要打平需要交易所反过来给 1.2 到 2 个基点的返佣；按散户现货费率（10 个基点）算，亏损会放大 6 到 9 倍。
2. **亏在逆向选择。** 成交那一刻的价差收入几乎是 0，成交后 5 秒平均亏 1 到 1.5 个基点。挂单主要是在价格正好冲过来的时候被成交的，也就是"只有在你错的时候才会被成交"。
3. **库存控制（v1）管的是风险，不是单笔质量。** 平均库存降到 v0 的 1/5 到 1/8，一小时亏的钱不到 v0 的一半，但主要是因为成交少了；按每单位成交额算，SOL 上好一些，BTC 上反而差一些。
4. **盘口不平衡信号是真的，但没能变成交易优势。** 它能解释未来 1 秒价格变化的约 11%，而且在样本外很稳定。v2 在回放的 8 组设置里有 7 组比 v1 好 0.15 到 0.6 个基点，但在实时测试里 BTC 略好、SOL 略差，差距都在一个标准误左右，不能算显著。可能的原因：信号只把公允价移动了不到一个最小价位，大多数时候根本不会改变报价。更有效的用法也许是在薄的那一侧直接撤单。
5. **速度主要起防守作用。** 延迟越低，挂着的旧报价越少，成交越少，大多数情况下亏得也越少（BTC 的 v0 从 500 毫秒的 -1.87 基点改善到 5 毫秒的 -0.42 基点），但在任何延迟下都没有转正。
6. **永续合约并不领先现货。** 这是我最初的假设，被数据推翻了。在 50 毫秒的精度下两者同步，真正有预测力的是盘口不平衡。
7. **回放和实时完全一致。** 用实时测试录下来的数据回放，1573 笔成交逐笔相同。

**这些结论和我们最开始聊的完全对得上**：做市的钱不在教科书的报价公式里，而在费率（返佣）、订单流（跟谁做对手盘）和速度上。一个散户用公开模型在币安最热门的交易对上做市，结果就是稳定地小亏。

## 6. 面试可以怎么讲

**30 秒版本**：
> 我用币安的实时行情做了一个做市模拟器，实时纸面交易和回放回测共用一套引擎，回放可以逐笔复现实时结果（1573 笔全部一致）。我实现了固定价差、Avellaneda-Stoikov 和加入短期信号三个版本，重点做了成交模型和盈亏拆解，并按"前 20 分钟校准、之后样本外检验、再加一小时实时测试"的流程做实验。结论是在零手续费下所有策略都亏 0.35 到 2 个基点，亏损来自逆向选择：成交后 5 秒平均亏 1 个多基点。盘口不平衡信号有稳定的预测力，在回放里减少了亏损，但实时测试没有稳定复现。要打平需要 1 到 2 个基点的返佣，这也解释了为什么做市是拼费率、订单流和速度的生意。

**可能被追问的问题和思路**：

- *你的成交模型可能有什么偏差？* 讲第 3 节的四条规则，以及"不影响市场"和"延迟只算了下单部分"两个简化。
- *为什么价差收入是负的？* 大部分成交是"盘口越过我的价格"这一类，成交那一刻中间价已经越过了我的挂单价。
- *Avellaneda-Stoikov 的参数怎么定？* γ 是风险厌恶，k 是成交概率随距离衰减的速度。本项目用前 20 分钟数据做了小网格校准，之后的实时测试是样本外。更严谨的做法是直接从数据拟合"挂单距离 vs 成交频率"来估 k。
- *永续合约领先现货吗？* 这是我原本的假设，但在这份数据里，100 毫秒级别上两者几乎同步，盘口不平衡的预测力更强。能讲出"假设被数据推翻"的经历是加分项。
- *如果给你真实资金，你会先做什么？* 先拿到更低的费率档位（或做市商返佣计划），再考虑更快的网络位置（交易所同区域服务器），然后才是改模型。

## 7. 你可以自己动手的改进（由易到难）

1. **换币种**：`python -m mmsim paper --symbol DOGEUSDT`，对比大跳价（tick 大）和小跳价的币，看排队位置的影响。
2. **加一个信号**：比如最近 1 秒的主动买卖成交量差（order flow imbalance），在 `signals.py` 加一个类，在 `engine.py` 的 `_state` 里传给策略，再用 `research` 验证它的预测力。
3. **校准 k**：统计"挂单距离中间价 x 个基点时，每秒被成交的概率"，拟合 λ(x) = A·e^(-kx)。
4. **跨交易所**：在 OKX 挂单，在币安对冲库存（`feeds/okx.py` 已经有了）。
5. **更真实的盘口**：用币安的增量深度流（diff depth）维护完整订单簿，替代 20 档快照，让排队估计更准。

## 8. 常用命令

```bash
pip install -e ".[dev]" && pytest                          # 安装并跑测试
python -m mmsim paper --symbol BTCUSDT --minutes 30         # 三个策略同时实时纸面交易
python -m mmsim record --symbol SOLUSDT --minutes 60 --out data/sol.jsonl.gz
python -m mmsim research --data data/sol.jsonl.gz --max-minutes 20      # 用前 20 分钟研究信号
python -m mmsim sweep --data data/sol.jsonl.gz --skip-minutes 20 --latencies 5,50,200
python -m mmsim backtest --data data/sol.jsonl.gz -s as_signal -p beta_imb=0.6
python -m mmsim reproduce --data data/paper_xxx.jsonl.gz    # 验证回放和实时一致
```
